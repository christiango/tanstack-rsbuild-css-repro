# TanStack Start + Rsbuild SSR CSS reproduction

An unpatched test app demonstrating incorrect route stylesheet discovery when Rspack extracts a shared component. No authentication, loaders, UI library, application fallback CSS, private dependencies, or dependency patches are involved.

## Reproduce

Prerequisites: Node 22.12+ and pnpm 11.25.0. Tested with Node 24.15.0 on macOS arm64.

```sh
pnpm install
pnpm exec playwright install chromium
pnpm repro
```

`pnpm repro` builds the production app and runs browser tests with JavaScript disabled. On the pinned baseline it exits with code 1: two tests fail and the home-route control passes. The assertions express the desired behavior and must pass after an upstream fix.

```sh
pnpm test
```

The independent Node tests also express desired behavior. On the baseline, two assertions fail and the acyclic control passes. These tests do not require a browser or a build of this app.

To validate that the reproduction behaves as documented, including a control build:

```sh
pnpm verify:repro
```

This command expects the known failures, requires the browser tests to pass with shared extraction disabled, and exits successfully only if those expectations hold. It restores the failing shared-extraction build at the end. This is a baseline verification command, **not** the command for accepting a fix.

To inspect the app manually:

```sh
pnpm start
```

Open <http://127.0.0.1:4317/alpha> and <http://127.0.0.1:4317/beta>. Disable JavaScript before refreshing to hold the SSR state. With JavaScript enabled, the missing styles load during hydration and can mask the problem.

## Observed versus expected

| Route | Expected CSS | Observed on the pinned baseline |
| --- | --- | --- |
| `/` | Root only | Root only |
| `/alpha` | Root, Alpha, shared header | Also receives Beta CSS |
| `/beta` | Root, Beta, shared header | Missing shared header CSS |

Beta's header computes to `display: block`, not `grid`, and is about 79px tall instead of 64px. Numeric chunk filenames and which route suffers the omission can depend on compilation/traversal order. The tests assert styling and isolation, not hashes or numeric chunk IDs.

The CSS custom properties prefixed `--repro-` are test markers in the real CSS Modules. They are not fallback styles or DOM attributes used to repair rendering.

## Smallest relevant graph

The source dependencies are:

```text
Alpha -> Header -> Header.module.css
Beta  -> Header -> Header.module.css
```

Each route also imports its own CSS Module. The Rspack cache group in `rsbuild.config.ts` extracts `src/components/` modules shared by two async routes. `minSize: 0` and `enforce: true` make the tiny fixture deterministic instead of padding it to reach the default size threshold.

The emitted loading groups contain:

```text
Alpha group: [shared-header, alpha]
Beta group:  [shared-header, beta]
```

TanStack's Rsbuild normalizer turns all sibling chunks into mutual `imports`:

```text
alpha         -> shared-header
beta          -> shared-header
shared-header -> alpha, beta     # not source dependencies
```

The CSS collector then encounters these cycles. It returns an empty result for an in-progress chunk but caches partial results reached below it. A route inspected later can receive an incomplete cached CSS set. Fully traversing this graph without correcting the false edges can instead leak other routes' styles.

This evidence locates the defects in **TanStack's interpretation of Rspack's graph and its CSS collector**. It does not establish that Rspack emits incorrect bundles.

## Diagnostics and controls

- `dist/repro/graph.json`: real emitted chunk files, normalized imports, CSS associations, and source-module dependencies. Produced by a read-only build-capture plugin; it does not modify the compilation or manifest.
- `dist/repro/verification.json`: generated by `pnpm verify:repro`, containing unit results and baseline/control browser results.
- `test-results/`: Playwright traces for failed browser checks.
- `REPRO_SHARED=0`: disables shared extraction in the client compiler. Dynamic route imports remain split. No app source or CSS changes in the control.

The app reproduced the failure before the diagnostic plugin was added. The diagnostic plugin can be removed from `rsbuild.config.ts` without being part of the fix.

All reports are generated and ignored by Git. Review generated paths and stack traces before attaching reports to a public issue.

## Verify a fix in TanStack

The repository intentionally contains **no proposed implementation patch**. A passing browser test alone is insufficient if the fix broadens every route's CSS dependencies.

Relevant upstream implementation files:

- `packages/start-plugin-core/src/rsbuild/normalized-client-build.ts`
- `packages/start-plugin-core/src/start-manifest-plugin/manifestBuilder.ts`

The fixtures in `tests/manifest.test.mjs` can be adapted to TanStack's own test runner. They currently use the installed ESM build's `registerClientBuildCapture` and `buildStartManifest` exports because the lower-level source helpers are not exported by this published build.

For testing a built local TanStack checkout, temporarily create `pnpm-workspace.yaml` here with an override pointing at that package:

```yaml
overrides:
  '@tanstack/start-plugin-core': link:../router/packages/start-plugin-core
```

Adjust the path to your checkout. Install and build that checkout's dependencies first using TanStack's contributing instructions. The package must have current `dist/esm` output. The override must affect both the direct test dependency and React Start's transitive dependency; changing only the direct dependency can test one implementation while building the app with another.

Then run:

```sh
pnpm install
pnpm test
pnpm repro
```

Both commands must pass normally with shared extraction enabled. A local checkout on a newer incompatible API may require updating the pinned Start/Router packages together; record those versions with the results.

Before accepting an upstream fix, extend upstream coverage for concatenated modules, CSS-only chunks, entry/vendor siblings, real dependency cycles, dynamic imports, repeated collection in different orders, and Windows paths. This minimal fixture proves the reported failure; it is not a substitute for TanStack's full bundler and framework test matrix.
